# Posting Stop responsiveness (2026-11-03)

Stop immediately signals the batch token, shows Stopping on active batch workers and marks untouched queue rows Cancelled before submission in the UI. It does not mutate queued job state while workers could still be reserving it; final cancellation persistence remains after all workers unwind. Submitted/confirmed outcomes are unchanged.

Worker keyboard restoration stays mandatory. Cancellation skips optional Clear recent apps and emulator closure; neither LD9 nor LD14 Clear recent implementation was changed. Worker status reflects keyboard restoration rather than displaying a misleading completed state, and never-started staggered workers are finalized as Cancelled when the batch unwinds. Leases remain held until worker completion, preventing overlapping automation.

Stopped-batch finalization defers optional confirmed source deletion, keeping its durable deletion state pending for later reconciliation. It does not delete local sources in an untracked background operation that could race a new queue. Media-count refresh runs independently with a 15-second cooperative cancellation deadline, cancellable gate/history/per-page observation checks and no cancelled-result UI application; the next preparation or ViewModel disposal cancels it. Synchronous filesystem calls already executing cannot be forcibly interrupted. Normal successful finalization retains existing source deletion/count refresh behavior.

Validation: actual isolated desktop Stop check verifies prompt cancellation/Stopping, unchanged submitted and confirmed states, no device operations and finalization completing while the count-refresh gate is deliberately held. Repeated against main-output desktop diagnostic after user closure. Six cleanup/Part-runner regressions passed. Main Debug build passed with zero warnings/errors after fresh app absence check, including final worker-status adjustment. No live posting, forced app termination, production history change or package. In-flight device commands, mandatory keyboard restoration and durable history writes may still take time; no instant-stop guarantee.
