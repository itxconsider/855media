# Editor CPU filter budget

Implemented 2026-10-23 after inspecting current job settings read-only: Fast Native, square crop, Original1x target, light brightness/contrast/saturation adjustments, 2x speed, Original frame rate and no facial clarity/denoise/deinterlace.

The existing GPU-resident resize optimization intentionally declines these effects. A measured hybrid experiment (CPU crop → CUDA upload/resize → download → CPU grade) was slower than the native filter graph on the local synthetic fixture. No hybrid GPU path was enabled and no effects were dropped.

The selected improvement limits both FFmpeg simple and complex CPU filter pools per job to clamp(logical cores / 2, 1, 4), including the CPU encoder fallback. The 20-core 265K therefore gets four filter threads per worker rather than a default full-machine filter pool for every concurrent job. Decoder/encoder settings, crop/grade order and values, speed, audio processing, output dimensions, cancellation and queue limits remain unchanged. Logs show `[CPU Budget]` with the effective pool size. Hardware utilization and results vary with source resolution, effects and simultaneous jobs; there is no general speed guarantee.

Local comparative benchmark: synthetic 1280x720 H.264 source looped to 960 frames (32 seconds), crop/scale to 1080 square, brightness .02 / contrast 1.06 / saturation 1.08, 2x playback plus atempo=2 AAC, H.264 NVENC P2, actual MP4 output. Two alternating runs on the busy PC: default filter threads 1.385/1.329 seconds elapsed and 3.594/3.063 CPU-seconds; four threads 1.288/1.303 seconds and 2.547/2.344 CPU-seconds. Mean CPU time was about 27% lower and elapsed time about 5% lower. CPU-seconds are accumulated process CPU time, not a claim about Task Manager's instantaneous percentage. The user's source files and running queue were not altered. Benchmark script/data are in `artifacts/editor-effects-check`.

Validation: 175 Editor tests passed, one existing speech-isolation integration test skipped. Actual FFmpeg framemd5 output for the crop/grade/speed graph matched exactly with automatic versus bounded filtering. Full service square/grade/2x export completed and retained expected video/audio duration. Existing real CUDA/recovery/queue/part/grading tests passed. Report: `artifacts/editor-effects-check/filter-threads.trx`. Desktop build passed with zero warnings/errors in the reused isolated `artifacts/instagram-browser-build` output. Running app and 3.1.9 ZIP unchanged; no restart or package was performed.
