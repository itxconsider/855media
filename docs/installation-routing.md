# Installation-scoped automation endpoints and locks

Validated 2026-10-29. LDPlayer 9 index 45 and LDPlayer 14 index 45 no longer share an application automation HTTP port or device lock when an installation path is provided.

PFlowInstallationRouting canonicalizes installation directories and ldconsole/dnconsole executable paths, including case and trailing separators. A hashed installation/index key identifies the route. Host automation ports are persisted under %AppData%/855Media/routing/ports.json, serialized through a cross-process file lock and committed by replacing a completed temporary file. Allocations use ports 20000–59999, resolve hash collisions against existing allocations and reject damaged/duplicate registry values instead of silently reassigning them. Port selection is application namespace allocation, not a guarantee that arbitrary unrelated external software cannot occupy a port.

AtxAgentClient.ForInstallation provides a cached client per installation, with separate per-client state/port caches, shared HTTP lifetime and tap-event forwarding. LDPlayerService, clipboard link access, Bloks, keyboard, UI automation and posting toast paths use the explicit installation client. The current PageSwitchLiveCheck diagnostic now uses the same route and installation-scoped lease.

PFlowDeviceLease accepts an optional installation path. Normal desktop posting/Fetch/ScreenTime/management/cleanup paths pass the configured installation; native account/session services obtain it from their navigator. Same-installation/index calls share both in-process and file locks. Different installations with the same index use separate keys. Account bindings already contain installation-based instance identity and are unchanged. The application still has one configured LD folder per run; this does not introduce a multi-installation device browser or relabel historical records.

Compatibility: index-only Atx/lease APIs retain their legacy route/lock namespace. External or older diagnostic callers must provide installation context to participate in the new isolation. Existing release archives and stored accounts/Pages are unchanged. The underlying emulator's ADB transport selection is not redesigned here; simultaneous same-index live operation on both emulator products has not been certified. Android 14 connectivity/foreground reader failures documented in release-3.2.4.md remain unresolved.

Validation: 244 focused existing/new Atx, LD service, account and native Fetch checks passed in artifacts/installation-routing/focused.trx. Six routing cases passed separately in routing-final.trx: canonical/persistent ports, concurrent allocations and HTTP route separation/client lifetime, invalid registry rejection, forced hash collision, explicit LD service routing and same-installation exclusion with different-installation concurrency. Synthetic HTTP handlers and test registries were used; no live switching/posting was tested. Read-only Android public-ID comparison during routing audit was inconclusive and is not used as an ownership assertion or routing shortcut.

Main Debug 3.2.4 built with zero warnings/errors after explicit user closure and fresh absence verification. No app termination, publication, production account/history/queue edit or package. One cohesive routing improvement credited once: 1/10 toward 3.2.5. Existing ZIPs unchanged.
