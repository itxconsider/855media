# Prepare multiple post types together

Prepare post queue now offers independent Reel, Photo and Story checkboxes. Reel remains selected by default. One Prepare action snapshots the choices and runs the existing per-type preparation in Reel, Photo, Story order within the same busy guard, loading overlay and final queue save. Choices are disabled during preparation. No selection reports guidance without adding jobs. Legacy selected-type index setters still select one corresponding type for existing callers.

File/series min/max applies separately to each chosen type. Daily maturity/custom capacity is shared: jobs queued by an earlier type consume remaining capacity before the next type. Existing source selection, Part-group ordering, source-file reservation and duplicate guards remain intact. A type without available configured media adds no rows; this does not stop other selected types. Preparation does not publish anything, and existing execution-time access checks remain in force.

Validation: actual view-model preparation with separate synthetic Reel/photo/Story files and an isolated history database queued all three types in one call and enabled their run flags. Empty choice added no rows; repeat preparation did not duplicate files. A two-post custom daily limit capped combined types at two rows. Account/search/filter/render diagnostics also passed. Build of the main project into 855Media/bin/Debug/net10.0 passed with zero warnings/errors after the user confirmed the running app was closed. Logs: artifacts/multi-type-queue-build.log and artifacts/multi-type-queue-check.log. No package produced; live preparation remains pending.
