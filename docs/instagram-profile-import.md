# Faster Instagram profile import

## Using the updated flow

Open a profile or its Reels tab, select Photos / Videos & Reels / both, and start Auto-Scroll. Once links appear, press Import and choose the destination. Auto-Scroll can continue finding posts while media is resolved and downloaded. Import waits for collection to stop, then drains the collected links. Switching tabs still pauses discovery, but does not cancel the import of links already found. Stop cancels further import; downloads already queued have separate Stop actions in Download Manager.

Enable Settings → Downloads → Skip existing files for resume. When retrying in the same destination with the same profile/media/name/translation/caption settings, a complete post is skipped only if all recorded media items have matching active queue jobs or completed history backed by nonempty files of the recorded sizes. Caption sidecars must exist when requested. Failed/cancelled, deleted, zero-byte, size-mismatched, wrong-source/post/destination and legacy item-ID-less records cannot authorize whole-post resume. Incomplete posts are resolved again, but matching individual items are not queued twice. Empty orphan placeholders no longer cause the new browser import queue to skip a download.

The post-membership journal survives restart. The browser's discovered link list does not: after restart, collect links again; verified completed posts then avoid individual-post reprocessing. Existing file-name skipping still applies to older downloads, but old history without item IDs cannot safely prove complete carousel membership. Turn Skip existing files off to explicitly import again. Clear resets current browser links/media capture, not downloaded files/history.

## Capture and fallback

`InstagramProfileCapture` observes successful JSON responses already requested by the embedded profile browser and reads inline structured JSON at document readiness/import. Eligible routes are owned HTTPS feed, profile clips and GraphQL endpoints. It sends no additional API request and exports no cookies or tokens. Parsing runs off the UI thread with two response reads at most, five-second read limits, bounded input/depth/traversal and retained-data limits (5,000 posts / eight million characters). These are capture-cache limits; uncached collected posts still use the detail reader.

`InstagramProfileMedia` requires an exact post code and matching profile username, explicit caption or explicit captionless data, and known media types. Carousels require the declared complete child count. Photos need original dimensions, matching aspect ratio and a rendition at least as large as those dimensions; a large preview is insufficient. The largest supported candidate is retained with its exact signed URL. Videos require a direct video rendition, never a cover/blob. Unsupported summaries fall back to the existing post reader, preserving media order, caption and carousel indices. This does not promise a camera-original file beyond what Instagram provides.

Capture is memory-only, discarded on navigation/profile/owner change, Clear or detach, and disabled on access expiry. Known expired or near-expiry signed URLs fall back. URLs without explicit expiration are retained at most 15 minutes; explicitly unexpired URLs can be retained up to two hours. Main-view sign-in/rate-limit guards apply even to cached/resumed work. An observed feed HTTP 429 immediately signals import cancellation and pauses scrolling; there is no automatic rate-limit retry. Missing post detail remains sequential and paced. Collection still uses its existing 2.5-second scrolling rhythm and can end at a loaded bottom or stall.

`InstagramImportProgress` stores only post codes, media IDs/types and caption-required flags in a bounded JSON-lines journal under `%APPDATA%\855Media\instagram-import`. Scope is hashed from destination/profile/media type and output preferences. Appends avoid rewriting the full profile each time; compaction uses an atomic replacement. A torn/corrupt record does not establish completion. Download history gains an optional `SourceItemId`; existing history remains readable. Completion still comes from actual queue/history/file checks, not the journal alone. Downloads retain the configured concurrency, H.264 conversion pipeline, and caption saving behavior.

- All **247 downloading Core tests passed**, including full-size versus preview/crop selection, captions, mixed/complete/incomplete carousels, ownership/type contradictions, signed expiry, corrupt checkpoints, restart isolation, cancellation/access guards, sequential fallback pacing, a 1,000-link cached/resumed run with zero post requests, and discovery continuing after the first item is queued.
- **44 actual offscreen WebView checks passed**: 21 existing Instagram, 13 new capture/streaming, and ten Facebook checks. Locally intercepted profile responses verified exact signed media/captions, zero individual-post navigations, real collector mutations joining the import, owner/navigation/access/Clear/disposal/expiration guards and HTTP 429 cancellation signaling.
- Focused actual desktop checks passed history/item/source/post/destination/file/sidecar resume guards, inactive access, ten deactivate/reactivate cycles, Stop, changed view owner and detachment. Run with `ResponsiveUiCheck --instagram-import-only`.
- Main Debug **3.2.4** built with zero warnings/errors after a fresh check showed the app closed. Main Core SHA-256 matches tested Core; main desktop assembly matches the focused desktop diagnostic. No app termination or release ZIP was performed.

Evidence is in `artifacts/instagram-profile-import`: `tests/downloading.trx`, `browser-checks.txt`, `desktop-checks.txt`, `build.txt` and `validation.json`. The broader ResponsiveUiCheck stopped before its Instagram section at the unrelated older **Wide tables not restored** dashboard assertion. That failure remains unresolved; only the focused run is claimed successful. An initial synthetic carousel fixture reused one identical asset URL and correctly hit the existing deduplicator; distinct fixtures corrected that test. A diagnostic synchronous UI wait was also corrected to avoid blocking its synchronization context.

No live authenticated profile throughput or completeness was certified. Instagram response shapes may change; strict fast-path misses use the viewer. Missing private/deleted/unloaded content, Stories and Highlights remain outside this collector. Scan a profile's Reels tab separately when Reels are absent from its main grid. No speed multiplier or complete-account archive is promised.
