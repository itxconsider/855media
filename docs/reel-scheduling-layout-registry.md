# Reel scheduling layout registry

Added five format1/v1 registrations: reel.scheduling-entry.v1, reel.scheduling-options.v1, reel.schedule-date-picker.v1, reel.schedule-time-picker.v1 and reel.scheduled-settings.v1. New screen/control enum values are appended to preserve previous numeric values. Default catalog JSON regenerated; existing user catalogs are not overwritten.

The supplied screenshots describe the initial settings entry, both option selections and schedule-summary text, Android calendar and clock/keyboard variants, and final Reel Settings with a Schedule button. SelectedPostNow/SelectedScheduleLater roles require native checked/selected evidence rather than inferring selection from a date string. ScheduleSubmit is a distinct control role, never Publish; no worker consumes it yet. No date/time parsing, job settings, picker navigation or submission flow is enabled by this change.

Scheduling options/pickers and scheduled settings exclude background registry surfaces. Partial native picker markers do not expose options behind the dialog. Controls require a recognized surface and unique usable visible/enabled in-bounds targets. Foreign packages, authentication, pending publication, passwords and unrelated editable fields are rejected. Native time-entry EditText fields are restricted to known Android hour/minute IDs. A missing or unsupported hierarchy remains unavailable.

Validation: all50 focused registry/catalog/welcome checks passed, including14 new synthetic screenshot-derived scheduling cases. They cover allfive screens plus keyboard time entry, both selected states, displayed summary, duplicate/disabled/hidden/offscreen Done, partial picker and foreign nodes. Main Debug3.2.4 built zero warnings/errors after fresh app-absence checks. No live LD9/LD14 capture or interaction certification: Android resource IDs and hierarchy relationships are provisional adapters until real dumps are collected. No production settings/data, publication, Graph, Recents changes or package.
