# Post history flow and UI

Validated 2026-10-29. History now uses a virtualized, read-only, sortable/resizable table for creation time, LD, Page/account, media type, outcome, Part number, caption/file and cleanup. Horizontal scrolling remains visible; default refresh order is newest creation time first.

Search supports combined LD/target/caption/file/Part terms. Outcome filters distinguish review-required, published, retryable, failed/cancelled and active records. Date filters use inclusive local calendar days for Today, seven days and thirty days. Summary counts describe the complete history while the visible count describes the filtered list. Review-required evidence takes priority over a superficially Confirmed state; uncertain submissions never enter the retryable filter.

Visible selections survive filtering and refresh by job ID; filtered-out selections are removed. Acknowledgment resets when selection, filters or review evidence changes. Select needing review expands a dedicated review area. Read-only details show full source, caption, error, evidence, Part key and publication timeline. Review and details toggle independently. Review controls scroll with a visible scrollbar and wrapping action/time rows so their buttons remain reachable at narrow widths. A caught clipped animated-expander layout was replaced with direct disclosure toggles; final narrow expanded rendering and action reachability pass.

Published/not-published review still uses the existing transactional stale-snapshot check, explicit evidence, acknowledgment and publication-time validation. Marking not published permits retry; it does not automatically submit a new post. Cleanup remains a separate explicit action. Busy state is checked again after device-lease waits before changing review outcomes or starting cleanup. Source/history schemas, duplicate protection and Part continuation are unchanged.
