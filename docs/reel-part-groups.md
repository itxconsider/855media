# Reel Part groups

Implemented in source; not yet packaged. EP/Episode grouping is deferred.

Open a Page's settings, enable **Keep video parts together** under its Reel source settings, and save. It is off by default. Existing queued posts retain their settings. The selection range counts series for enabled Pages and individual files for other Pages. Sequential retains the existing from/to index-range semantics; Random chooses a random count within the range.

Supported names include `A Part 1.mp4`, `Part 2 A.mp4`, `A_Part03.mp4`, and `[013]_Part1_original1x.mp4`. Matching ignores case, normalizes spaces/underscores/hyphens in the remaining series name, and keeps different folders separate. Parts sort numerically, including Part 2 before Part 10. The complete name except the Part marker identifies the series; a bracketed number alone is not a global identifier. Caption text files remain attached to their respective videos. Queue rows show a separate Part group column and preserve captions.

Random chooses a series, then queues its available parts in order as separate posts. Duplicate part numbers, multiple Part markers, or names with no remaining series identity are blocked with warnings. Part 1 through the highest available number must be present or confirmed in the same target's history. Two-part videos are supported: the app cannot infer a missing final Part 3 from filenames alone. EP filenames receive ordinary individual-file selection.

Each part uses a normal daily slot and posting interval. If capacity is insufficient, the selected series manifest is saved with the Page before dispatch rows are created. Prepare the queue again on a later authorized run to resume unfinished groups before choosing new ones. Midnight does not trigger posting. Repeated preparation excludes reserved files. Current target bindings, content availability, subscription checks, duplicate detection and publication verification remain in effect.

The selection limit also applies to saved unfinished series. With both min and max set to 1, preparation resumes only the first unfinished series for each selected target, even if an earlier selection saved multiple series or the visible queue was cleared. Other saved series remain deferred with a notice. Repeated preparation does not skip a first series whose parts are already queued; finish it before continuing to the next series. Clear queue removes dispatch rows but preserves unfinished-series progress.

The posting runner checks that every earlier part is confirmed for the same Page/profile, owner, package, device and account binding. Failed, submitted and uncertain uploads do not advance progress. Later parts are held until History review or the existing safe retry flow resolves the earlier job. A subsequent start replans held rows and repeats this check; it does not automatically retry the earlier upload. Group manifests, queue metadata and history survive restart.

Keep series names unique within each source folder. A confirmed part whose content changes under the same series name is blocked from using the old confirmation; give the replacement a new series name. Missing files in unfinished series must be restored or the source corrected. Turning grouping off preserves the saved unfinished series but uses ordinary file selection for newly prepared jobs.
