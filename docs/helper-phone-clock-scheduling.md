# Phone clock for first-post scheduling

Implemented November 8, 2026. The Android companion remains named **885Helper** (package `com.media885.helper`); the desktop is 855Media.

885Helper 1.0.4/code 5 exposes a protected, local `/clock` provider query. It samples Android UTC epoch milliseconds, elapsed boot milliseconds, timezone ID, UTC offset seconds and local date/time from one wall-clock sample. The status response advertises clock protocol 1 and includes the snapshot. The helper screen shows Date & time and timezone. Reads require the existing DUMP permission and shell/root/self check, do not request public IP, and do not change timezone, clock, VPN or IME.

In Run settings → Posting & devices → Publishing time, enable Schedule Reels on Facebook, choose a running LD under Phone clock source, and click **Use LD time + 1 hour**. The app fills the first publication time from the phone's UTC sample plus 60 minutes, rounded up to a whole minute, and fills its timezone ID. Both fields remain editable; Save configuration retains them. Prepare a new queue to use them. All targets in that queue share this chosen reference time; the existing scheduler converts each frozen UTC instant to each target LD's local picker time. Already prepared rows remain unchanged.

The desktop reads through installation-owned direct shell ADB, automatically installing the same-signed APK if clock protocol 1 is missing. A fresh query is made after any upgrade, so install time does not age the snapshot. The parser requires compatible protocol, positive epoch, elapsed boot value, bounded 15-second read, phone time within two minutes of host UTC, recognized timezone and agreement between local time/offset/UTC using desktop timezone rules. Missing, stale, unsupported or inconsistent clocks do not overwrite settings. Ambiguous DST first-post times are rejected by the existing scheduling rules. Fractional offsets and date rollover use the phone timezone rather than the PC timezone.

The UI command requires an idle desktop and running selected LD, uses a device lease and 45-second cancellation deadline, and rejects installation/device/index/selection/schedule changes during the read. It never launches a stopped LD. Existing scheduling clock checkpoints prefer the helper, revalidate it and reject zone changes before submission; the prior validated ADB clock checks remain compatibility fallback when no valid helper response is available. No new auto-submission behavior is added.
