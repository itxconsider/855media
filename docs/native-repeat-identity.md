# Native repeat identity verification — posting and ScreenTime

Historical native settings-link implementation. Current source retains Graph account/target activation but uses [session-bound own-profile UI](session-ui-identity.md) for repeat/publication checks, without rereading UID links or opening Page Settings. The one-Graph account-session experiment remains in the existing 3.1.7 ZIP. Fetch is unchanged.

This phase changes posting and ScreenTime only. Fetch account/Page discovery and its Graph detail reads are unchanged, as requested. Graph is retained for fresh account/target activation. Fresh account startup proof can be handed to the immediately following operation using its existing one-use, 15-second process/UI-bound handoff, including ScreenTime.

After live Graph UID verification succeeds, an in-memory native identity scope binds the mapped account/target, emulator instance, package and Facebook process to a digest of the authenticated token and owner. Raw credentials are not retained by this scope, logged or written to history. The digest is correlation evidence rather than authorization: every repeat operation must independently observe the current actor's own numeric UID through Facebook's native profile/settings UI, then confirm that the authenticated process/session remains unchanged.

For Pages, the existing native Your Page link route verifies the Page ID or its verified persona delegation. For personal profiles, a fresh Your profile link must resolve to the assigned owner UID. Visible username links can use the existing supported Facebook web link resolver; this is not a Graph request. The repeat path currently requires a supported visible own-profile link; it does not add a clipboard-only layout route. Missing/ambiguous links, mismatching UIDs, foreign/input/login surfaces, changed credentials or unsupported layouts do not authorize work.

Posting checks use the native scope on subsequent operations for the same active target. A target change or explicit account/process/session invalidation requires fresh verification. Scopes are cleared at batch initialization and are excluded from job JSON; saved job history cannot restore authorization. A native failure does not silently fall back to repeated Graph reads within the operation. Existing exception handling clears active identity evidence so a later authorized run can perform fresh account verification.

New Reel publication checks use the job's native scope before profile refresh and after matching the new post. They never call Graph. The current actor may be navigated from a supported Reel viewer to its own profile/settings and back using fresh controls, but this path does not switch personas, restart Facebook, invoke login recovery or submit another post. Missing proof leaves publication unconfirmed for review. Existing caption/time matching, profile refresh, target binding checks and uncertain-publication handling remain in effect.

If fresh Graph is unavailable, the existing full native pre-operation lookup remains available. It does not manufacture a Graph-bound scope. A Reel without such a scope will not obtain a publication identity confirmation through an unverified fallback; it remains subject to review. Cookies, names, saved IDs and root data alone are never sufficient identity proof.

Validation: 342 focused Graph/native identity, startup handoff, target-session, publication and ScreenTime tests passed. Native scope tests verify three independent repeat lookups, process/token/owner/foreground changes, changes during lookup, unsupported UI, cancellation, serialization exclusion, binding/target mismatches and captured Page/personal settings-link routes with no persona switch or restart. Desktop build passed. Fixtures and fake services were used; no live LD job or publication was run. Native navigation may take longer than Graph on some layouts and requires live validation before assuming all supported Facebook variants work.

Trace events: `identity.live-uid` records fresh Graph/native fallback verification, `identity.native-uid` records repeat native verification, and `publication.native-uid` records native publication identity proof. Neither credential bytes nor their digest are emitted. Test build: `artifacts/native-repeat-uid-build/855Media.exe`. No new distribution package was produced.
