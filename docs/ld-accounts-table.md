# LD-Accounts table

The account management tab now uses a DataGrid instead of large cards. Search matches LD number/name, account name and owner UID without changing the rows or saved account flags. Filters show All, Needs attention, Fetch, ScreenTime or Posting. Default order and LD-column sorting use numeric instance indices. Columns show bulk selection, LD, account, UID, cached Page count, mapping status and editable task flags. Selection and LD remain frozen; a visible horizontal scrollbar reaches the remaining columns on smaller screens.

The warning wall is replaced by a compact visible/total/attention count; affected accounts show Needs attention with their mapping reason in a tooltip and selected-row details. The summary tooltip retains the full mapping diagnostic report. Mapped status explicitly does not imply live authentication. Selecting a row opens its credential, mapping, transfer/removal and automatic-login/rotation controls. Existing commands and validation are retained. Options still need saving.

Select visible selects only visible valid mappings. Bulk apply/save uses explicitly selected valid accounts across filters; the summary reports the total selection and visible account count. Thus turning Fetch off under the Fetch filter may hide the edited row but cannot lose its selection or make its changes unsaveable. Clear selection clears all selection. Search/filter changes do not silently enable tasks or alter saved settings.

## Bulk option switches

Three Fetch/ScreenTime/Posting switches replace the six On/Off buttons. On means every explicitly selected valid account has the option enabled; Off includes mixed selection (explained in tooltips). Switching sets the option for selected valid accounts only. Switches are disabled when no accounts are selected or editing is blocked. Changes still require Save selected accounts. Actual VM checks covered all three on/off directions and preservation of unselected accounts; table rendering and details checks also passed. Successful build: artifacts/account-switch-validation, logs account-switch-validation-build.log and account-switch-check.log. Normal output build was locked by the running app; it was not terminated.
