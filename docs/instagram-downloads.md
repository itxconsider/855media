# Instagram photos, videos and Reels

Open **Downloader → Instagram Web Browser**. Sign in to Instagram inside this browser, navigate to a profile, post or Reels tab, select the media type, then choose **Auto-Scroll → Import**. Import opens the collected posts sequentially in one temporary WebView sharing the embedded browser's profile. No cookie export is required for this route. Switching tabs stops collection/detail resolution and hides the inactive native browser.

When media selection or another application dialog opens, the native Instagram/Facebook browser surface is hidden so it cannot cover the dialog. Closing/Cancel restores the active browser without canceling the import. See [browser dialog visibility](browser-download-dialog-visibility.md) for the seven-Reel regression and validation limits.

Pasting one Instagram URL into **Universal Downloader** and choosing Download also opens this browser flow. It stays on the browser instead of switching prematurely to Download Manager. Profile/post links default to **Photos only**; Reel links and profile Reels tabs default to **Videos & Reels only**. The selector also offers **Photos + videos & Reels**. The browser is created lazily when first opened.

- `https://www.instagram.com/nample/`: open the profile, collect its loaded post links, then import their photos or videos.
- `https://www.instagram.com/nample/reels/`: open the Reels tab, collect its loaded Reel links and import their videos. This does not substitute the profile's photo grid.
- `https://www.instagram.com/p/SHORTCODE/`: import the selected post's photos or mixed carousel. Each image/video becomes its own queue item.
- `https://www.instagram.com/reel/SHORTCODE/`: resolve its signed video rendition in the browser, then download through the existing H.264 compatibility pipeline.

The collector retains canonical post/Reel links across virtualized rows and deduplicates post codes; it never imports the profile grid's image URLs. The detail reader matches the requested post code, prefers post-bound structured metadata and otherwise uses the selected post's article/viewer. It chooses the largest supplied image rendition from candidates, display resources or viewer srcset, retaining the exact signed URL. DOM carousels advance only their own Next control. Original post captions remain separate from filenames; post-caption More can expand, while comments and image-alt text are excluded. An explicitly captionless photo does not borrow generated title text.

Reel downloads use a signed video rendition resolved from post metadata or a single visible player; offscreen neighbors, cover images and blob URLs are not accepted as video assets. Missing or ambiguous media, unsupported layouts, login/checkpoint pages and browser rate-limit prompts stop the current import explicitly. This is the largest rendition Instagram supplies, not a promise of the camera-original file. Stories, inaccessible posts, shared redirect links, profile avatars and expired signed-URL recovery are outside the browser import's scope.

The shared photo downloader streams to a temporary file, uses the source site's referer without sending account cookies to the image CDN, rejects HTML/login pages and cleans up canceled partial transfers. JPEG/PNG bytes are retained; other image formats require successful FFmpeg conversion. Existing files are replaced only after transfer/conversion succeeds.

Photo-only imports use the same destination-folder queue flow as Facebook photos. Mixed/video imports use the existing selection dialog; photos keep their `.jpg` queue items regardless of the selected video/audio container. Enable **Save title to text file** to save the original caption beside each image as UTF-8. Download setup dialogs receive the real license service, and browser actions, imports and queued downloads retain execution-time subscription checks. Stop and Clear remain accessible after access expires.

Auto-Scroll uses 2.5-second steps and reports the loaded bottom or a stall rather than claiming every Instagram post was collected. Import uses one temporary renderer and waits 2.5 seconds between posts. Stop cancels resolution and retains collected links. Cancellation is also checked before/while queueing; items already queued use Download Manager's Stop actions. Unsupported post resolution stops before queueing the resolved batch. Only posts visible to the signed-in account can be read; separate tabs/albums and unloaded or inaccessible content are not automatically included.

The reported HTTP 429 occurred on the previous direct profile-info lookup, before a feed/Reel page was collected. The new browser route avoids that custom profile API lookup; it does not remove Instagram's restrictions. Complete verification shown by Instagram, and wait if the site limits activity. No automatic retry loop or fallback to lower-resolution grid images is used. HTTP 429 itself means the server is limiting requests; it may supply a Retry-After period ([RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585#section-4)).

The previous direct API resolver remains available for mixed multi-URL Batch Mode; it still needs an exported Instagram `sessionid` cookie in **Settings → General → Apply Instagram cookies**, and can still receive API rate limits. That cookie store is separate from signing in to the embedded browser; this flow does not export or synchronize browser cookies. Its profile listing uses web profile-info/feed endpoints, photo posts use media-info, and Reels use a paginated connection based on [Instaloader's implementation](https://github.com/instaloader/instaloader/blob/master/instaloader/structures.py). These endpoints/query IDs can change independently of the app. Single URLs use the browser route described above.
