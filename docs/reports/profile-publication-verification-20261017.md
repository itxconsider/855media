# Verify Reel publication on the target profile

New bound Reel/Video jobs now record a read-only baseline of the target profile's visible Reels before media staging. After a publication message, toast or upload notification—or after the normal confirmation wait expires—the publisher checks the same target's profile before accepting success.

The check revalidates the immutable LD binding and fresh Graph actor/owner identity, including Page persona delegation when required. It opens the current actor's own profile and selects a Reels tab aligned with the profile Photos tab, rather than the global Reels navigation button. Up to three visible Reel/Video cards are examined. Missing or unsupported UI, an unknown baseline, unavailable identity proof or missing media tools yields no proof.

A new candidate must have a thumbnail that differs from baseline cards and matches a sampled source frame. FFmpeg crops the card's outer badges/corners, compares 24×24 RGB samples against source frames at 0, 0.5, 1, 2 and 4 seconds, and rejects uniform images or excessive pixel differences. Only one matching candidate is permitted. That card is opened read-only and must expose the exact full caption, expected author, and a publish time consistent with the attempt. Existing baseline IDs, multiple IDs/links, processing states, authentication prompts, foreign apps and identity changes are rejected. Post ID and Facebook Reel URL are saved when the UI exposes them.

The baseline has a 30-second deadline. Post-publication checking has a 45-second total budget and at most two attempts. Inputs use observed profile tabs, media cards and Back controls; no Share, Like, comment, overflow or account-switch action is performed by the verifier. A failed or ambiguous check leaves the job Unknown and retains its files. Confirmation from an actual matching profile Reel, or acknowledged manual publication review, is required for these jobs' cleanup. Picture and Story confirmation paths are unchanged by this feature.

Validation uses synthetic accessibility layouts, mocked device observations, and actual FFmpeg extraction with generated video and PNG media. The media check matched the source and rejected an unrelated video. This work did not submit a live post or verify compatibility with LD-11's current live Reels grid; unsupported live layouts remain Unknown for review. The scan currently examines the first three visible cards and recognizes only supported Reel/Video accessibility labels. Truncated captions and missing recent-time labels cannot confirm a post.

Final checks: 190 posting, Story, native Reel, target-session, continuation, publication-profile and confirmation tests passed. Desktop build passed with zero warnings and errors. Actual media extraction returned a 1,728-byte thumbnail vector, accepted its source video and rejected the unrelated video.
